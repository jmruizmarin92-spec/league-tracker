# Sessions & Rounds

A Session is a single dated instance of a league where players show up, get paired into rounds (Swiss pairing), report match results, and see live standings/scoring. This is the most complex domain in the app.

## Routes (`app/leagues/[slug]/sessions/[sessionSlug]/**`)

- `page.tsx` — main session page. Pinned above the fold: breadcrumbs, status badge, meta line and the three links (display/league standings/league archetypes), join/leave controls (self-service, only while `status === "setup"`), the logged-in player's "my match" card (`MyMatchCard`, which also carries the round clock players see) and the my-archetypes editor (locked once session is `complete`) — the archetype card stays out of the tabs on purpose, it's a one-time action per player and burying it makes it easy to forget before pairings. Everything else sits in the `PageTabs` strip: **Rondas** (generate round N + recommended-round hint for admins, then the nested `RoundsTabs` per-round view with the admin round timer), **Clasificación** (standings table), **Participantes (n)** (admin only — check-in tally, registered roster, waitlist, Pokémon-ID copy tool), **Gestión** (admin only — add participant/late-join options, create a managed player, edit session details, status toggle setup/active/complete, delete session). A `RealtimeRefresher` runs while the session isn't complete, so timer/pairing/result changes land without a reload.
- `display/page.tsx` — public "big screen" live display. Renders the current round's pairings + a live `RoundTimer` (read-only) and a standings table, refreshed via `RealtimeRefresher` (Supabase Realtime + 30s poll fallback). No admin actions.

## Server actions

**`app/actions/sessions.ts`**: `createSessionAction` (RPC `create_session`, redirects to new session), `updateSessionAction` (RPC `update_session`), `joinSessionAction`/`leaveSessionAction` (self join/leave), `setMyArchetypesAction`/`adminSetParticipantArchetypesAction`/`setArchetypeVisibilityAction` (archetype picks, public/private — see `docs/features/archetypes.md`), `createSessionPlayerAction` (create a managed player + add to session), `adminAddParticipantAction` (wraps `admin_add_late_participant` RPC, forwarding late-join options `missed`: none/loss and `entry`: next/current/bye), `adminRemoveParticipantAction`, `adminSetCheckedInAction` (RPC `admin_set_checked_in`), `setSessionStatusAction`, `deleteSessionAction`.

Note: `createSessionAction`/`updateSessionAction` call the underlying RPCs with 6 args (league/name/starts_at/location/cost/capacity), while migration `0033_session_format.sql` redefined `create_session`/`update_session` to require 9 args (adding `best_of`, `rounds_planned`, `round_timer_minutes`) — worth double-checking the action call sites are passing the newer signature.

**`app/actions/rounds.ts`**: `generateRoundAction` (`useActionState` shape, returns `GenerateRoundState = { error? }`) — computes standings via `lib/scoring`, orders the active roster by standings, builds "already played" and "already had bye" sets from existing matches, calls pure `generateSwissPairings` (`lib/pairing`), persists via RPC `create_round`. A matchup never repeats within a session: if `generateSwissPairings` returns `null` (every remaining option is a rematch — the field is round-robin exhausted) the action refuses with a Spanish error message instead of creating the round, and `create_round` RPC errors are surfaced the same way. `reportMatchAction` (RPC `report_match`), `deleteRoundAction` (RPC `delete_round`), `startRoundTimerAction`/`pauseRoundTimerAction`/`resumeRoundTimerAction`/`clearRoundTimerAction` (round countdown timer RPCs).

## Lib logic

- `lib/sessions.ts` — `listSessions`, `getSessionBySlug` (cached, joins league), `listParticipants` (with `is_me` flag), `getMyParticipation`.
- `lib/rounds.ts` — `getRounds`, `getSessionMatches` (stable order: table_number, nulls/byes last, then created_at), `getActiveParticipantIds` (registered, not dropped).
- `lib/pairing.ts` (pure, unit-tested) — `recommendedRoundCount(n)`: official Play! Pokémon Swiss round table (8→3 … 2506→12), falls back to round-robin below 4 players, log2 extrapolation above. `generateSwissPairings(ordered, played, hadBye)`: Swiss pairing that never repeats a matchup — pairs top-down, each player against the nearest lower-ranked opponent not yet played, but every pick is checked with a lookahead (Edmonds' blossom perfect-matching test on the remaining "fresh opponents" graph, which is not bipartite) so the top pairs shift instead of leaving the bottom of the field with a forced rematch (the old greedy pass did exactly that: with A,B,C,D and only C–D played it paired A–B and then repeated C–D). On an odd count the bye goes to the lowest-ranked player without a prior bye, climbing the standings (bye-eligible players first, then those who already had one) if that's the only way to pair everyone else fresh; the bye is always placed last → highest table number. Returns `null` when no rematch-free pairing exists at all, so the caller blocks the round rather than repeating a matchup. Covered by `lib/pairing.test.ts` (including a 40-player / 8-round sweep and a full 6-player round-robin).
- `lib/scoring.ts` (pure, unit-tested) — Win=3, Draw=1, Loss=0, bye=win. Standings sorted by points → OWP (opponents' win %, averaged over real opponents faced, each opponent's rate floored at 25% and excluding their own byes) → wins → player id. A `loss` result (solo, player2 null) is a 0-point played round with no opponent, used for late-joiners who missed earlier rounds. Covered by `lib/scoring.test.ts`.

## Components

- `create-session-form.tsx` / `edit-session-form.tsx` — session create/edit forms (datetime-local, venue select or free text, cost, capacity).
- `generate-sessions-button.tsx` — league-level bulk session generator (calls `app/actions/leagues`, not session-scoped).
- `page-tabs.tsx` — the top-level tab strip, shared with the event page (`line` variant, so the round pills nested inside the Rondas panel still read as a lower level of navigation). Panels are server-rendered React nodes passed in as props: the tabs only decide what's visible, they never defer a fetch. The active tab is client state, so a server action (reporting a result, flipping check-in) keeps you where you were; it is validated against the current tab list on every render instead of being corrected in an effect, because a server action can remove the active tab under you — setting the session to `complete` drops the admin panels, deleting the last round can empty Rondas. Admins in `setup` land on Participantes (check-in is the job at that point), everyone else on Rondas.
- `generate-round-button.tsx` — the admin "Generar ronda N" button, a `useActionState` form around `generateRoundAction` so the action's refusal (no rematch-free pairing left, or an RPC error) renders inline next to the button; a plain `<form action>` would swallow it. Disabled while results are pending or the action is in flight.
- `rounds-tabs.tsx` — tabbed round view, always snapping to the latest round, win/draw buttons per match, admin delete-round, and the latest round's `RoundTimer` — the timer block here is admin-only (it carries the start/pause/reset controls); players read the clock off their own match card instead, so it isn't rendered twice.
- `round-timer.tsx` — countdown derived from server `endsAt`; admin can start/pause/resume/reset. Renders nothing when the round has no timer and the viewer isn't an admin. Passing `notify` (title/body plus the three toggle labels) adds an opt-in bell that fires a browser `Notification` at time-up; the session page and `my-match-card` pass it, the shared display screen deliberately does not. Opt-in is stored per device in `localStorage` under `league.timer-alerts` and read through `useSyncExternalStore` (both values are client-only, so reading them during render would break hydration, and pushing them into state from an effect trips the `react-hooks/set-state-in-effect` rule). `Notification.permission` wins over the stored flag: revoking permission in browser settings turns the bell back off, and a `denied` permission renders it disabled with the "blocked" label. The permission prompt is only opened from the button's click handler, since browsers require a user gesture. The alert is a `setTimeout` aimed at the server's absolute `endsAt` rather than a watch on the 1s render tick, because a backgrounded tab throttles the tick; duplicate alerts from two mounted timers (a player who is also an admin) collapse via a shared notification `tag`.
- `my-match-card.tsx` — pinned "your match" widget with win/draw/lose report buttons, plus the latest round's clock (read-only, `admin={false}`) inline in the card header next to the round/table badges. This is the only place a non-admin sees the countdown, which is why `page.tsx` mounts `RealtimeRefresher` on any non-complete session: without it a player's page would not pick up an admin starting, pausing or resetting the timer until they reloaded.
- Player names in pairings (`rounds-tabs.tsx`, `display/page.tsx`, `my-match-card.tsx`) are truncated with an ellipsis (`title` attribute holds the full name) so a long name never wraps onto a second line and breaks the pairing layout.
- `participants-list.tsx` — the admin roster, shared with standalone events (`docs/features/events.md`). Each row is `[check-in switch] [name (+ optional Pokémon ID underneath)] [archetype chips] [edit archetypes + remove]`; the switch is unlabelled (the label survives only as `aria-label`) and the archetype picker expands full width below its row when opened. The list owns the check-in state for its rows, so the optional "solo pendientes de check-in" filter (registered list only) reacts immediately when a switch is flipped, without waiting for a server round-trip. The waitlist renders a second instance with no filter. Note the header tally (`checkedInCount`) is server-rendered and only updates on revalidation, so it can lag the switches by a moment. Callers pass `contextId` + `contextIdField` (`session_id` by default, `event_id` for events) and optional `extraFields` for the archetype picker's hidden inputs; rows can carry a `pokemonId` (omit the key entirely to hide the line — `null` renders the "Sin ID" placeholder) and an `extra` node rendered under the row (events use it for the list editor).
- `add-participant-form.tsx` — participant picker plus late-join fieldset (missed: none/loss; entry: next/current/bye) shown once rounds exist.
- `realtime-refresher.tsx` — subscribes to `matches`/`rounds`/`session_participants` changes filtered by `session_id`, triggers `router.refresh()`.

## Database

- `sessions`: id, league_id, name, slug (unique per league, date/name-derived), starts_at, location, cost, capacity, status (setup/active/complete), best_of (1|3), rounds_planned, round_timer_minutes, created_by/at.
- `session_participants`: (session_id, player_id) PK, status (registered/waitlisted), joined_round, dropped_round, archetype1/2, archetype_public, checked_in (on-site check-in, informational only — it gates nothing).
- `rounds`: id, session_id, number, status, timer_duration_seconds, timer_ends_at, timer_remaining_seconds.
- `matches`: id, round_id, session_id, player1_id, player2_id (null=bye), result (pending/p1_win/p2_win/draw/bye/loss), table_number (stable per-round seating, null for byes/losses), reported_by/at.

Key RPCs (security-definer): `create_session`/`update_session`/`delete_session`, `join_session` (setup-only)/`leave_session`, `admin_add_participant`/`admin_add_late_participant` (bye-fill/loss backfill logic)/`admin_remove_participant`, `set_session_status`, `create_round` (assigns table numbers, blocks if pending matches exist)/`delete_round`, `report_match`, `set_participant_archetypes` (locked post-complete)/`admin_set_participant_archetypes`, `admin_set_checked_in`, timer RPCs. Realtime publication is enabled for `matches`/`rounds`/`session_participants`.
